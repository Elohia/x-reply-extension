# X 快速回复 · 产品思路

> 版本 v0.4.0 · 2026-11-08
> 一句话：**在你看的那条推文下面，给你三句像人说的话，点一下就进回复框，发不发你自己按。**

---

## 一、先说我不要做什么

做这个之前先划三条线，否则很容易做成一个"AI 洗稿机"：

1. **不做自动发帖**。自动发＝账号被封的加速器，也是用户最怕的事。产品只负责"写"和"填"，"发"永远是人按。
2. **不监听页面**。上一版用 MutationObserver 监听整页 DOM，X 每秒变几百次，主线程被打满，用户反馈"卡"。
   这一版直接不监听：只留一个悬浮按钮，点的时候才读当前推文。
3. **不做"通用 AI 套壳"**。用户缺的不是模型，是**知道在 X 上什么叫一条好回复**。这是产品的立身之本。

---

## 二、用户是谁

| 人群 | 典型场景 | 现在的做法 | 痛点 |
|:--|:--|:--|:--|
| **出海独立开发者 / 小团队** | 每天要在 X 上回 20–50 条，涨粉接单 | 自己憋、复制粘贴、发完就撤 | 写不快、写得假、不知道说什么 |
| **AI / 技术博主** | 回复同行大 V，借评论区曝光 | 只点赞不回复 | 怕说错、怕像 AI、怕没信息量 |
| **跨境 / 电商卖家** | 盯客户和同行的帖子 | 只用翻译 | 语气不对、没人接话 |
| **刚起号的人** | 前 100 天靠互动破零 | 手忙脚乱 | 不知道"回什么算有效互动" |

共同点：**他们不是不会写，是没时间憋，且怕一句话说错**。所以产品卖的不是"生成"，是"**判断 + 起步句**"。

---

## 三、核心洞察（这一条决定产品形态）

我们把 341 条真实中文回复抓下来做了统计：

| 指标 | 真实回复 | 通用 AI 的默认写法 |
|:--|:--|:--|
| 长度中位数 | **30 字** | 80–150 字 |
| 一句话占比 | **74%** | 多段、带小标题 |
| 问句占比 | **9%** | 总是以问句结尾 |
| 带数字占比 | **60%** | 泛泛而谈 |
| 套话占比（学习了/说得好） | **2%** | 常见 |

**结论：AI 写的回复不像人，不是因为文笔差，是因为"长度、句式、角度"三件事都错了。**
真人回复的主体是**"接一句 + 补一个具体信息"**，不是提问、不是总结、不是客套。

所以产品的护城河不是模型，是**这套语料口径**——它被打包在插件里（`src/reply-style.js`），
新用户装完即用，不依赖任何本地环境。谁想抄，得先抓够样本、再对一遍统计。

## 四、产品形态

### 一句话交互

```
滚到想回的推文 → 按 Alt+R（或点右下角「回」）→ 三条候选 → 改一改 → 填入回复框 → 你按发送
```

### 三个设计决定

**1）一个按钮，不侵入页面**
不给每条推文注入按钮（注入 = 监听 = 卡）。只有一个悬浮按钮 + 快捷键。
用户的心智负担也小：**"我要回这条"是一个主动动作，不是满屏按钮**。

**2）三条角度固定，不让人选择困难**

| 角度 | 什么时候用 | 占比参考 |
|:--|:--|:--|
| 接一句 | 顺着他说，补一个具体信息 | 60% |
| 顶一句 | 不完全同意，给反例或边界 | 30% |
| 收一句 | 短判断，不解释 | 10% |

**3）"具体信息"是硬约束**
每条必须落一个数字 / 亲历 / 可执行动作。推文里没有数字，就留 `【你的数字】` 占位——**让本人填，不替他编**。
这条既是质量保证，也是合规底线（不制造假信息）。

## 五、用户旅程

| 阶段 | 用户动作 | 产品要做的 | 失败兜底 |
|:--|:--|:--|:--|
| 装 | 加载扩展（30 秒） | 不填 Key 也能用（内置模板） | 面板写明"填 Key 可换模型" |
| 试 | 随便找条推文按 Alt+R | 1 秒内出三条 | 页面没加载出推文 → 提示"滚到推文上再点" |
| 用 | 挑一条、改数字、填进回复框 | 一键填入、只写一份 | 找不到回复框 → 提示手动点「回复」 |
| 留存 | 每天回 20+ 条 | 记住语气偏好、统计条数 | 计数只在本地，不上传 |
| 付费 | 觉得值 | 走自己的 API Key 或订阅托管额度 | —— |

## 六、功能分层（MVP → V2）

**MVP（当前 v0.4.0）**
- 悬浮按钮 + Alt+R，读当前推文
- AI / 本地模板双通道（无 Key 走模板）
- 三条候选 + 自检（太长、套话、占位符没填）
- 一键填进回复框 + 候选条换一条
- Key 只存本地，不上传

**V2（下一个版本）**
- **回复记忆**：记录回过的推文 ID，避免重复回同一条（本地）
- **语境感知**：识别"求推荐 / 报错求助 / 晒数据 / 观点争论"四种帖型，切换角度配比
- **多语言**：英文回复按英文语料口径（长度 8–25 words）
- **语气记忆**：从用户改过的草稿里学他的口头习惯（本地学习，不上传原文）

**V3（可选，看付费意愿）**
- 托管额度（订阅制，用户不用自己申请 Key）
- 线程/长文草稿（配合 X 的 Note Tweet）
- 多平台（小红书/即刻），共用同一套"短句 + 具体信息"引擎

**明确不做**：自动发帖、批量互关、刷互动、代运营。

## 七、商业模式

| 模式 | 说明 | 优劣 |
|:--|:--|:--|
| **免费 + 自带 Key**（现在） | 插件免费，用户填自己的 API Key | 口碑好传播快；但普通用户不会申请 Key |
| **订阅托管额度**（主推） | 9–19 元/月，含 N 条生成，后台走我们自己的 Key | 体验最好；需要成本控制与账号安全 |
| **买断 / 企业版** | 团队多账号、自定义语料 | 客单价高；落地重 |
| **引流品** | 免费版导流到"X 运营陪跑"服务 | 与主业协同 |

判断：**先免费打口碑，订阅只做"不想折腾 Key"的人**。X 的付费用户本来就愿意为效率付钱。

## 八、指标

| 层级 | 指标 | 目标（前 3 个月） |
|:--|:--|:--|
| 激活 | 装后 24h 内至少生成 1 次 | > 60% |
| 留存 | 次日 / 7 日仍用 | 40% / 20% |
| 价值 | 人均每天生成条数 | 5–15 条 |
| 质量 | 填入后未修改直接发的比例 | 观察项（太高说明模板化，太低说明没用） |
| 转化 | 免费→订阅 | 3–5% |
| 口碑 | Chrome 商店评分 | ≥ 4.5 |

关键反指标：**"生成后立刻关掉面板"的比例**——高说明三条都不合用，是语料口径出问题了。

---

## 九、风险与合规

| 风险 | 说明 | 对策 |
|:--|:--|:--|
| **X 平台规则** | X 禁止批量自动化互动；自动发帖高风险 | 只写不发；不做批量；把"发送"永远留给人 |
| **账号安全** | 插件理论上能读到页面内容 | 只读推文正文，不碰 cookie/私信；权限最小化（host 仅 x.com） |
| **Key 泄露** | 用户 Key 存本地 | 存 `chrome.storage.local`；不经过任何中间服务器 |
| **内容责任** | AI 可能编数字 | 硬规则：没有数字必须留占位符；不生成可核查的事实性断言 |
| **X 改版** | 选择器失效 | 选择器集中管理 + 失败给明确提示，不静默失败 |

## 十、为什么这件事值得做

1. **需求真实且高频**：想涨粉的人每天都在回帖，回帖质量直接决定曝光。
2. **切入点小、护城河清楚**：不是"又一个 AI 写作"，而是"X 回复这一个动作"，靠语料口径建立差异。
3. **成本极低**：一条回复约 400 tokens，按 deepseek 价格 ≈ 0.001 元；免费版也能扛。
4. **和现有资产协同**：`dsh-x-scroll` 已经有一套 X 的写操作闸门与台账，未来可复用。

---

## 十一、下一步（按优先级）

1. **补齐"回复记忆"**：同一推文不重复推荐，避免用户看到重复草稿
2. **帖型识别**：求推荐 / 报错 / 晒数据 / 争论，四类各配一套角度权重
3. **英文语料**：抓 200 条英文回复做同样统计，英文用户是更大的盘子
4. **上架 Chrome 商店**：截图、隐私说明（只读 x.com、不上传内容）、评分引导
5. **定价实验**：先放"赞助"链接测意愿，再决定要不要做订阅托管
